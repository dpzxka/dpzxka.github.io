鸿蒙新项目架构搭建-MVVM与三方库选型实战

前言

新项目落地，第一件事不是写业务代码，而是搭架构。架构搭得好，后续开发事半功倍；搭得不好，三个月后就开始”屎山”重构。

本文将从零搭建一个鸿蒙新项目的完整架构，核心内容包括：

  1. MVVM架构设计：Model-View-ViewModel分层与数据流
  2. 目录结构规划：模块化划分与职责边界
  3. 三方库选型：路由、网络、序列化、日志、图片、弹窗
  4. 基础能力封装：网络层、缓存、工具类
  5. 工程化配置：代码规范、构建配置、多端适配

一、MVVM架构设计

1.1 为什么选MVVM

鸿蒙ArkUI天然支持响应式UI，与MVVM模式高度契合：

架构模式 数据流 ArkUI适配度 复杂度
MVC 双向依赖 ⭐⭐ 低
MVP Presenter持有View引用 ⭐⭐ 中
MVVM ViewModel通过@State驱动View ⭐⭐⭐⭐⭐ 中
MVI 单向数据流 ⭐⭐⭐⭐ 高

MVVM的核心优势：ViewModel不需要持有View引用，通过@State/@Observed/@Track等装饰器实现数据驱动UI自动更新。

1.2 MVVM分层设计

1.3 数据流设计

单向数据流原则：

  • View只负责渲染，不处理业务逻辑
  • ViewModel只处理业务逻辑，不直接操作UI组件
  • Model只负责数据获取，不关心业务含义

2.2 模块职责边界

模块 职责 依赖方向
pages 页面渲染、用户交互 → viewmodel, components
viewmodel 业务逻辑、状态管理 → repository
repository 数据获取策略、缓存 → service, model
service 网络请求、本地存储 → model
model 纯数据模型 无依赖
components 可复用UI组件 无业务依赖
utils 无状态工具函数 无依赖

8.2 常见陷阱

陷阱 正确做法
用npm安装依赖 必须用ohpm
ViewModel持有View引用 通过@State驱动UI更新
网络请求散落在页面中 统一走Repository层
无缓存策略 二级缓存（内存+磁盘）
无错误处理 拦截器统一处理+页面兜底
无主题管理 使用ThemeColors统一管理
无路由守卫 敏感页面检查登录状态

总结

本文从MVVM架构设计、目录结构规划、三方库选型、基础能力封装四个维度，给出了鸿蒙新项目架构搭建的完整方案。核心原则：

  1. MVVM分层：View只渲染，ViewModel只逻辑，Model只数据
  2. 模块化：职责单一，依赖方向明确
  3. 三方库选型：网络用axios，图片用imageknife，弹窗用smart_dialog
  4. 统一管理：网络层统一拦截、错误统一处理、主题统一配置

这套架构已经在多个项目中验证，可直接复用到你的新项目中。
