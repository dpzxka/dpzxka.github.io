一、@Component 装饰器深度解析

1.1 组件化的核心原理

@Component 装饰器是ArkUI组件化体系的基石。它装饰 struct 关键字声明的结构体，使其具备组件化能力。

关键规则：

  • 一个 struct 只能被一个 @Component 装饰
  • 必须实现 build() 方法描述UI
  • 成员变量支持默认值或构造函数参数初始化

1.2 组件生命周期

自定义组件的完整生命周期：

回调 触发时机 典型用途
aboutToAppear() 组件创建后、build前 初始化数据、订阅事件
onPageShow() 页面显示时 刷新数据、恢复状态
onPageHide() 页面隐藏时 暂停动画、保存状态
aboutToDisappear() 组件销毁前 取消订阅、释放资源

1.3 组件复用机制

ArkUI框架会缓存已创建的组件实例，通过 @Reusable 装饰器可以声明组件的复用策略：

复用流程：

  1. 组件被移出可视区域时，进入缓存池
  2. 新组件需要创建时，优先从缓存池获取
  3. 触发 aboutToReuse 回调，更新组件数据
  4. 避免重复创建，提升列表滑动性能

@LocalBuilder 是 @Builder 的变体，其 this 指向声明它的组件（而非调用点组件）：

选择建议：

  • 需要访问调用点组件的数据 → 用 @Builder
  • 需要访问声明组件的数据 → 用 @LocalBuilder
  • 不确定时 → 用 @Builder（更常用）

四、组件通信模式对比

模式 数据流 适用场景 复杂度
@Prop 父→子（单向） 展示型子组件 低
@Link 父↔子（双向） 表单输入组件 中
@Provide/@Consume 祖先→后代（跨层） 主题/配置等全局数据 中
@BuilderParam 组件插槽 容器组件布局 中
回调函数 子→父（事件） 子组件触发父组件操作 低

最佳实践：

  • 优先使用 @Prop（单向数据流更可预测）
  • 表单场景用 @Link
  • 全局状态用 @Provide/@Consume 或状态管理库
  • 避免在组件内直接修改父组件数据

六、常见问题

Q1：@Builder 和普通函数有什么区别？

关键区别：

  • @Builder 声明的是UI构建描述，框架会对其进行优化
  • 普通函数在每次 build() 时都会重新执行
  • @Builder 支持延迟执行和条件渲染优化

总结

本篇深入解析了ArkUI自定义组件的核心机制：

  1. @Component：组件化基础，支持生命周期和复用
  2. @Builder：UI构建函数，支持插槽和参数传递
  3. @BuilderParam：插槽机制，实现灵活的组件组合
  4. @LocalBuilder：局部Builder，控制this指向
  5. 数据流：@Prop/@Link/@Provide/@Consume 各有适用场景
