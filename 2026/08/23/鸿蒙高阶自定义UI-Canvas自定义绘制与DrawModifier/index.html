九、最佳实践

9.1 选择合适的绘制方式

场景 推荐方案 原因
简单2D图形 CanvasRenderingContext2D API简单，易上手
高性能绘制 DrawingCanvas GPU加速，性能更好
动态效果 DrawModifier 直接绑定组件，自动响应状态
底层控制 RenderNode 最大灵活性
复杂静态图形 OffscreenCanvas 预渲染避免重复计算

9.2 性能检查清单

  • Canvas面积不超过 10000×10000px
  • 避免在 onReady 之外的生命周期回调中频繁重绘
  • 使用脏区域标记而非全量重绘
  • 静态内容使用 OffscreenCanvas 预渲染
  • DrawModifier 的 invalidate() 合并多次调用
  • 及时释放不再需要的 PixelMap 资源

十、常见问题

Q1: Canvas 和 DrawModifier 有什么区别？

Canvas 是一个独立的画布组件，需要在 onReady 回调中手动执行绘制逻辑。适合需要完全控制绘制流程的场景。

DrawModifier 是绑定到现有组件上的绘制修改器，直接在组件的绘制流程中插入自定义逻辑。适合给现有组件添加装饰效果的场景。

Q2: 什么时候用 DrawingCanvas 而不是 CanvasRenderingContext2D？

从性能角度，DrawingCanvas（API 12+）使用GPU加速，在复杂绘制场景下性能更好。从API角度，CanvasRenderingContext2D 的API更接近Web标准，学习成本更低。建议：基础2D图形用 CanvasRenderingContext2D，高性能场景用 DrawingCanvas。

Q3: DrawModifier 的五个绘制方法执行顺序是什么？

依次为：drawBehind（内容背景）→ drawContent（内容）→ drawFront（内容前景）→ drawForeground（前景层，API 20+）→ drawOverlay（遮罩层，API 23+）。

Q4: 如何触发 DrawModifier 重绘？

调用 invalidate() 方法。该方法会标记组件状态已变更，触发组件的重新渲染。同步触发多个 invalidate 仅会触发一次重新绘制。

Q5: OffscreenCanvas 的典型使用场景是什么？

复杂图形预渲染（先离屏绘制再一次性传输）、多层合成（多个离屏Canvas分别绘制不同层后合并）、性能优化（避免在主Canvas上频繁重绘静态内容）。

Q6: RenderNode 和 DrawModifier 如何选择？

DrawModifier 适合大多数自定义绘制场景，直接绑定组件使用简单。RenderNode 提供更底层的控制，适合需要精细管理渲染节点树的场景（如配合 NodeController 动态创建节点）。
