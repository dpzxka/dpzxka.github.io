鸿蒙 AR Engine 进阶：人体骨骼点识别与跟踪——从骨骼定位到姿态交互

发表于2026-06-18|更新于2026-08-22|harmonyos
|总字数:6.5k|阅读时长:28分钟|浏览量:

前言

在之前的文章中，我们系统学习了 AR Engine 的各项空间感知能力：平面检测、场景网格、图像跟踪、高精几何重建、深度估计。这些能力都围绕一个共同主题——理解环境。它们让我们能够回答”房间里有什么””墙壁在哪里””物体有多远”这类问题。

但还有一类 AR 能力同样重要，却关注着完全不同的对象——人本身。

试想这样的场景：

  • 你对着手机做出健身动作，应用实时分析你的深蹲姿势是否正确
  • 你在屏幕前挥动手臂，AR 虚拟角色同步做出相同动作
  • 你做出”抬手”或”摇头”的手势，AR 菜单随之响应

这些体验的核心技术就是人体骨骼点识别与跟踪（Body Skeleton Tracking）。

在本章中，你将学到：

  • 人体骨骼点跟踪的技术原理与 20 个关键点体系
  • ARType.BODY 的会话配置与 ARFrame.acquireBodySkeleton() API
  • ARBody、ARBodyLandmark2D 的数据结构
  • 基于 Canvas 的骨骼叠层绘制
  • 基于关键点坐标的实时姿态识别
  • 性能优化与最佳实践

前置条件：人体骨骼点跟踪需要 API 23+（HarmonyOS 6.1.0+），且设备需支持 AR Engine 的 Body Tracking 能力。请确认你的设备已满足要求。

一、人体骨骼点识别能力全景

1.1 什么是骨骼点识别？

人体骨骼点识别（Body Skeleton Tracking）是 AR Engine 提供的一项身体姿态感知能力。它通过分析相机画面中的人体图像，实时估算出20 个关键骨骼关节在 2D 屏幕空间和 3D 世界空间中的位置。

与传统的计算机视觉姿态估计不同，AR Engine 的骨骼点跟踪充分利用了设备 IMU 和时序信息，能够在人物移动、旋转、部分遮挡的情况下保持稳定的跟踪，且帧率可达 30fps 以上。

1.3 数据类型

AR Engine 对人体骨骼点提供了两种维度的数据：

数据类型 API 维度 用途
ARBodyLandmark2D ARBody.getLandmarks2D() 2D 屏幕坐标 (x, y) 叠层绘制、UI 交互
ARBody 属性 trackId / timeStamp 人体实例标识 / 时间戳 区分多人体、数据同步

说明：当前 ArkTS API 层仅提供 2D 屏幕坐标（ARBodyLandmark2D），不提供 3D 世界坐标骨骼点。需要 3D 骨骼数据时，可结合深度图（ARFrame.acquireDepthImage16Bits()）与相机位姿自行重建，或等待后续版本开放。

1.4 典型应用场景

手势交互 抬手/挥手触发 AR 菜单 2D 手腕/肘部坐标
虚拟形象驱动 实时驱动 3D 虚拟角色的骨骼 3D 骨骼旋转
肢体控制游戏 体感游戏，如”切水果” 2D 手腕坐标轨迹
运动分析 分析跑步/跳跃姿态 3D 骨骼序列

七、API 对比：ARBody 与其他跟踪能力

能力 核心 API 数据维度 版本要求 相机方向
平面检测 type=WORLD → ARPlane[] 多边形面片 API 18+ REAR
图像跟踪 type=IMAGE → ARAugmentedImage[] 位姿 + 尺寸 API 18+ REAR
人体骨骼点 type=BODY → ARBody[] 20 个 2D/3D 关键点 API 23+ FRONT
深度估计 type=WORLD → 深度图 16-bit 逐像素 API 18+ REAR
高精几何 type=WORLD → 体素 体素网格 API 20+ REAR

关键区别：

  • 数据维度不同：骨骼点数据是”点”级别的，而平面/网格是”面”级别的
  • 跟踪对象不同：Body Tracking 跟踪的是运动的人体，其他能力跟踪的是静态环境
  • 相机方向不同：Body Tracking 通常使用 FRONT 摄像头（自拍），环境感知使用 REAR
  • API 版本不同：Body Tracking 是 API 23+ 的较新能力

八、性能与最佳实践

8.1 maxDetectedBodyNum 设置

  • 单人场景：设置为 1，最省性能
  • 多人场景：最大支持 2，但会增加 CPU/GPU 负载
  • 如果设置过大，引擎会尝试检测更多人体，可能导致帧率下降

8.2 相机方向选择

方向 适合场景 说明
FRONT 自拍 AR、健身指导 用户面对屏幕，上半身检测
REAR 外部人物跟踪 场景中其他人体的全身检测

8.3 光照条件

Body Tracking 对光照有一定要求：

  • 避免逆光：面部和身体过暗会导致关键点检测失败
  • 避免过曝：强光下人体边缘模糊也会影响精度
  • 最佳光照：均匀的环境光，人物与背景有明显对比

8.4 帧回调中的性能守则

8.5 Canvas 绘制优化

  • 使用 requestAnimationFrame 驱动绘制循环，与显示刷新同步
  • 不要在 Canvas.onDraw 中做骨骼数据解析
  • 使用 clearRect + 增量绘制，避免全屏重绘
  • 对于生产环境，考虑使用 AGP（ArkGraphics 3D）进行 GPU 加速渲染
