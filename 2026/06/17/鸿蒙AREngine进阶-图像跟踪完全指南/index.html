前言

在前两篇文章中，我们分别学习了 AR Engine 的基础能力（会话管理、平面检测、模型渲染）和进阶感知（点云、场景网格、着色）。本篇聚焦图像跟踪——识别现实世界中的二维图像并在其上叠加虚拟内容。

图像跟踪的典型应用场景包括：扫描海报触发视频播放、识别商品包装展示3D模型、翻开教材显示AR动画等。这些体验的核心技术就是图像跟踪——让 AR 设备识别并跟踪现实世界中的二维图像，在其上叠加虚拟内容。

在本章中，你将学到：

  • 图像跟踪的核心架构与两种工作模式
  • ARAugmentedImageDatabase 的创建与配置
  • ARAugmentedImage 的跟踪状态与位姿解析
  • 图像数据库的序列化与本地缓存
  • 完整实战：图片识别 + 3D 模型叠加
  • 图像选择与性能优化最佳实践

所有代码均遵循 HarmonyOS NEXT V2 装饰器规范，并基于 AR Engine API 18+。

前置条件：本文假设你已经熟悉 AR Engine 的会话创建和 ARViewContext.init() 流程。如果这是你第一次接触 AREngine，建议先阅读本系列第一篇文章《鸿蒙 AR Engine 完全指南》。

一、图像跟踪能力全景

1.1 什么是图像跟踪？

图像跟踪（Image Tracking）是 AR Engine 提供的一项重要能力：应用预置一张或多张参考图片到 ARAugmentedImageDatabase 中，AR 会话启动后，引擎会在每一帧相机画面中搜索匹配这些图片，一旦识别成功，就返回该图片在 3D 空间中的位置、姿态和尺寸信息。

有了这些信息，我们就可以在识别到的图片位置精确叠加虚拟内容——模型、动画、信息面板——并且让它们随着图片的移动而同步移动。

1.2 两种工作模式

AR Engine 的图像跟踪支持两种模式：

模式 核心 API 适用场景
添加本地图片 addImage(name, pixelMap, physicalSize) 运行时动态注册图片，方便更换内容
加载本地数据库 serialize() / deserialize() 预计算数据库文件，启动更快，适合固定内容集

两种模式的底层跟踪能力完全一致，区别在于数据库的构建时间：

  • 添加本地图片模式：在应用启动后调用 addImage() 逐张注册图片，引擎在内存中完成图像特征提取。灵活，但首次跟踪前需要额外的特征计算时间。
  • 加载本地数据库模式：提前将图片注册并调用 serialize() 导出为 .bin 文件，启动时直接 deserialize() 加载。省去了每次启动的特征提取步骤，启动速度更快。

1.3 能力速览

能力 说明 API 版本
图像识别 在相机画面中匹配预注册图片 18+
6-DoF 姿态跟踪 返回图像在 3D 空间中的位置和旋转 18+
物理尺寸估计 返回图像的实际物理尺寸（extendX/extendZ） 18+

多图同时跟踪 同时跟踪多张不同图片 18+

physicalSize 参数非常重要——它告诉引擎目标图片在现实世界中的实际宽度（单位：米）。这个数值直接影响跟踪的精度和虚拟内容的缩放比例。例如一张 A4 海报约 0.21m 宽，一张电影海报约 0.7m 宽。

2.2 ARAugmentedImage

当引擎在相机画面中成功匹配到参考图片后，会返回 ARAugmentedImage 对象。它包含了跟踪结果的所有信息。

注意：ARAugmentedImage 继承自 ARTrackable，因此 state（跟踪状态）和 type（跟踪类型）属性继承自父类。官方 ArkTS API 中没有 centerPose 属性——获取位姿统一使用 getPose() 方法（官方开发指南示例中即用 arImage.getPose() 获取图像中心位姿）。

ARAugmentedImage 状态机

图像跟踪的状态变化是理解其行为的关键：

状态 值 含义
TRACKING 0 正在跟踪中，位姿可信
PAUSED 1 跟踪暂时丢失（遮挡/移出画面），位姿为最近已知值
STOPPED 2 跟踪已停止，不再恢复 
    stateDiagram-v2
    [*] --> TRACKING: 图像被识别
    TRACKING --> PAUSED: 遮挡/移出画面
    PAUSED --> TRACKING: 图像重新出现
    PAUSED --> STOPPED: 超时/关键帧丢失
    STOPPED --> [*]
    
    note right of TRACKING
        位姿实时更新
        适合叠加虚拟内容
    end note
    note right of PAUSED
        位姿固定为最近值
        可保持虚拟内容可见
    end note
    note right of STOPPED
        不再更新位姿
        建议隐藏虚拟内容
    end note

处理建议：

  • TRACKING 状态：正常显示虚拟内容，实时更新位姿
  • PAUSED 状态：继续保持虚拟内容可见（最近位姿），可使用淡出效果提示用户
  • STOPPED 状态：隐藏虚拟内容，等待重新识别

四、基本配置与会话启动

4.1 配置 AR 会话

图像跟踪的会话配置与平面检测类似，核心区别在于 type 必须设为 ARType.IMAGE：

关键点：当 type: ARType.IMAGE 时，AR Engine 会优先运行图像识别算法。但注意这不意味着其他能力被完全禁用——平面检测、命中检测等能力仍然可用，只是引擎的优化重心会放在图像匹配上。

技术上，ARType.IMAGE 告诉引擎内部的特征提取器优先匹配 ARAugmentedImageDatabase 中的注册图片，同时会适当降低平面检测的灵敏度。如果你的应用既需要图像跟踪又需要平面检测，建议将 planeFindingMode 设为 HORIZONTAL_AND_VERTICAL 来获得最佳效果。

6.3 丢失跟踪后的策略

当图像跟踪进入 PAUSED 或 STOPPED 状态，应用应该怎么办？

场景 推荐策略
短暂遮挡（用户的手扫过画面） PAUSED → 保持内容可见，降低透明度
移出相机画面再回来 PAUSED → 内容保持在原位置，等待重新 TRACKING
长时间丢失（超过 5-10 秒） STOPPED → 隐藏内容，可能需要重新初始化跟踪
用户主动远离目标 跟踪自然丢失 → PAUSED → STOPPED，清理资源

七、图像加载失败原因分析

在练习过程中，你可能会遇到图片无法加载到数据库的问题。下面列出最常见的失败原因。

7.1 常见失败原因一览

原因 说明 解决方案
图片分辨率过低 < 50×50 像素，特征不足 使用 ≥ 300×300 像素的图片
纹理不足 纯色/渐变/模糊图片无法提取特征 选择有丰富纹理的图片
对比度过低 暗部细节无法识别 提高图片对比度
图片格式不支持 非标准格式 使用 JPEG 或 PNG 格式
物理尺寸偏差过大 physicalSize 与实际严重不符 测量实际图片物理宽度
数据库图片过多 > 30 张影响匹配性能 减少数量或分批加载
图片特征过于相似 多张图片特征重叠导致误匹配 选择特征差异明显的图片

好的参考图片应该满足以下条件：

    CHECK3 -->|否| REJECT3[拒绝: 需调整对比度]
    CHECK3 -->|是| CHECK4{尺寸 ≤ 1.0m?}

推荐图片特征：

  • 尺寸：≥ 300×300 像素，建议 500×500 以上
  • 纹理：包含文字、图标、复杂图案（如海报、包装、书封）
  • 对比度：明暗差异明显，避免全灰/全白/全黑
  • 长宽比：≤ 3:1（过长的条状图片跟踪效果差）
  • 格式：JPEG（照片类）或 PNG（图形类）
  • 物理尺寸：0.1m ~ 1.0m 之间

9.3 虚拟内容叠加的注意事项

当你在跟踪到的图像上叠加虚拟内容时，有几个关键点需要特别注意：

1. 坐标系对齐

getPose() 返回图像中心位姿（官方开发指南中 centerPose = arImage.getPose()）。如果你的 3D 模型锚点在底部中心，可以基于 getPose() 做 Y 轴偏移让模型”站立”在图像平面上：

2. 图像方向

extendX 是图像的水平宽度，extendZ 是垂直高度。在 AR Engine 的坐标系中：

  • X 轴向右
  • Y 轴向上
  • Z 轴指向相机

图像默认位于 XZ 平面上（Y=0），所以宽度沿 X 轴、高度沿 Z 轴。

3. 内容加载时机

不要在每一帧都重新加载 3D 模型。推荐的做法是：

  • image.state === TRACKING 时，如果模型未加载则加载，已加载则更新位姿
  • image.state !== TRACKING 时，保持模型但不更新位姿（或降低可见度）

十一、FAQ

Q1: 图像跟踪支持 GIF/动态图片吗？

不支持。addImage() 接收的是静态 PixelMap，GIF 只有第一帧会被提取为静态图像。如果你需要跟踪动态内容，应使用多张静态关键帧分别注册。

Q2: 为什么我的图片总是识别失败？

从最常见的可能性开始排查：

  1. 图片纹理是否丰富？（避免纯色/渐变 → 换图测试）
  2. physicalSize 是否准确？（用尺子量一下实际宽度）
  3. 光照是否充足？（在 100-500 lux 的环境测试）
  4. 图片是否过小/过大？（建议 0.1m ~ 0.5m）
  5. 相机是否对焦清晰？（确认 focusMode: AUTO）

Q3: 能同时跟踪多少张图片？

官方没有给出硬性上限，但实际测试建议：

  • 同屏 ≤ 5 张可获得稳定跟踪
  • 数据库中注册 ≤ 20 张
  • 超过建议值会导致单帧处理时间增加、跟踪稳定性下降

Q4: 从 PAUSED 恢复到 TRACKING 需要多长时间？

取决于图像重新出现在画面中的清晰度和特征丰富度。通常在 1-3 帧内（约 30-100ms）可以恢复。如果超过 5 秒没有恢复，引擎会自动转为 STOPPED。

Q5: serialize 生成的 .bin 文件能跨版本使用吗？

数据库文件与 AR Engine 版本相关。建议在 AREngine SDK 升级后重新生成 .bin 文件。不同设备型号之间一般可以通用。

Q6: 跟踪到的图像位姿在 PAUSED 状态还有效吗？

位姿值冻结在丢失跟踪前一帧的值，不再更新。如果你的应用对位姿精度要求高，建议在 PAUSED 状态时不要使用位姿数据做精确的交互反馈。

结语

本文系统地讲解了鸿蒙 AR Engine 的图像跟踪能力，从核心概念 ARAugmentedImageDatabase 和 ARAugmentedImage，到两种工作模式的完整代码实现，再到实战中的 3D 模型叠加。

图像跟踪是 AR 应用中最具表现力的能力之一——它让现实世界中的任意平面图像都能成为一个”AR 入口”。无论你是做博物馆导览、商品展示、互动广告还是教育应用，掌握图像跟踪都能给你带来丰富的创作空间。
