鸿蒙动画系统完全指南：从属性动画到显式动画再到转场动画

发表于2026-05-11|更新于2026-05-25|harmonyos
|总字数:3.6k|阅读时长:14分钟|浏览量:

动效是 modern App 体验中不可或缺的一部分。一个按钮的按下反馈、一个列表项的展开收起、一个页面的切入切出——这些细腻的动画不仅让界面看起来更专业，更重要的是给用户提供了操作后的即时反馈。

鸿蒙 ArkUI 提供了一套完整的动画体系，覆盖从最简单的属性变化到复杂的转场效果。这套体系核心可以归纳为三种动画类型：

一、动画三要素：时长、曲线、属性

在深入每种动画之前，需要先建立一个基础认知——所有动画的本质都是属性随时间变化。这个变化受三个因素控制：

时长（duration）：动画从开始到结束持续的时间，单位毫秒。300ms 是最常用的值，人眼感觉最自然。

曲线（curve）：控制属性变化的速度曲线，常见的有：

曲线 效果 典型场景
Curve.Linear 匀速 进度条、加载指示器
Curve.Ease 慢→快→慢（默认） 通用入场动画
Curve.EaseIn 慢→快 离场动画
Curve.EaseOut 快→慢 入场动画
Curve.EaseInOut 慢→快→慢，比 Ease 更平滑 通用

当然还有更高级的弹簧曲线和贝塞尔曲线，后面会讲到。

二、属性动画：最基础的声明式动画

属性动画是 ArkUI 中最简单、最常用的动画方式。它对组件上单个属性绑定动画参数，当该属性变化时自动以动画过渡。

七、常见误区

7.1 animation 放在错误的位置

.animation() 作用于它之前的可动画属性。这是 ArkUI 规定好的顺序，和 CSS 的 transition 声明顺序不同。

7.2 animateTo 不传 duration

animateTo 的 duration 默认值是 1000ms（在较新的 API 版本中），如果你只传了曲线没传时长，动画可能比你预期的慢得多。

7.3 弹簧曲线不用传 duration

八、总结

ArkUI 的动画体系可以用一句话概括：属性动画是”声明”，显式动画是”控制”，转场动画是”过渡”。

类型 API 核心特点 适用场景
属性动画 .animation() 声明式绑定，自动驱动 单个组件的属性变化
显式动画 animateTo() 集中控制，批量驱动 多组件/多状态同时变化
转场动画 .transition() 出现/消失过渡 组件创建销毁、页面切换
弹簧曲线 SpringCurve 物理弹性效果 按钮反馈、列表弹性滚动
自定义曲线 cubicBezier() 任意速度曲线 需要精确控制动画节奏

理解这三种动画各自的能力边界，再结合弹簧曲线和贝塞尔曲线的灵活运用，基本就能覆盖大部分 App 中动效需求了。

鸿蒙动画体系的知识密度很大，一篇文章很难穷尽所有细节。这一篇侧重于最核心的三种动画类型和曲线选择，后续可以根据实际需求再深入具体的专题，比如路径动画（MotionPath）、逐帧动画、组动画等。
